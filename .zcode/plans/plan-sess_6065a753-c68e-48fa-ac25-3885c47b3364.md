## Backend

**Stack**: Flask, Flask-Limiter, Flask-CORS, ldap3, Pillow, gunicorn. Python 3.12-slim. Lint with ruff, tests with pytest.

**Modules**:
- `config.py` — dataclass loaded from env; fails fast at startup on missing/invalid values (e.g. FLASK_SECRET_KEY strength, LDAP_URL scheme).
- `db.py` — stdlib `sqlite3`, WAL mode, schema auto-init, tiny query helpers.
- `codes.py` — code lifecycle over SQLite. Columns: `code_hash` (SHA-256 of token — tokens are 256-bit `secrets.token_urlsafe(32)` so a fast hash is fine), `code_hint` (first 4 chars, for admin `/list` display only, returned only via internal API), `groups` (JSON), `created_by`, `created_at`, `expires_at`, `used_at`, `used_by`, `revoked_at`, `failed_attempts`. Operations: create, lookup-by-hash, validate (unused + unrevoked + unexpired + under MAX_FAILED_ATTEMPTS), **atomic claim** (`UPDATE … SET used_at=? WHERE code_hash=? AND used_at IS NULL` — rowcount 0 = already used, prevents double-use races), revert-claim on LDAP failure (best effort), revoke, increment-failures + auto-invalidate at MAX_FAILED_ATTEMPTS.
- `validation.py` — pure functions, fully unit-tested: username `^[a-z0-9._-]{3,32}$` + reserved-name denylist (`admin`, `root`, …) + uniqueness via LDAP; names 1–64 chars, letters/spaces/hyphen/apostrophe (unicode-letters via `str.isalpha()` per char); email RFC-lite regex ≤254; password ≥12 chars AND pool-based entropy ≥60 bits (entropy = len × log2(charset pool: 26/26/10/33)) AND not in small embedded common-password denylist. No zxcvbn dependency.
- `images.py` — optional photo: check `Content-Length` + `MAX_CONTENT_LENGTH` before reading (default 2MB); magic-byte sniff (JPEG/PNG/GIF/WEBP) rejecting extension-only trust; Pillow `open()+verify()` → RGB convert → resize to ≤512×512 → re-encode JPEG q85 (re-encoding inherently strips EXIF) → bytes for `jpegPhoto`.
- `ldap_service.py` — all LLDAP operations, isolated for mocking: `connect()` (ldaps:// direct, or ldap:// + mandatory StartTLS; plain LDAP only if `LDAP_ALLOW_INSECURE=true`, documented dev-only), `create_user()` (add `uid=<name>,ou=people,<base>` with inetOrgPerson attrs: cn, sn, givenName, mail, userPassword, jpegPhoto), `add_to_groups()` (MODIFY_ADD `member` on `cn=<g>,ou=groups,<base>`), `list_groups()`, `user_exists()`.
- `errors.py` — stable machine error codes (`invalid_code`, `code_expired`, `code_used`, `code_locked`, `ip_locked`, `username_taken`, `validation_error` + per-field details) — frontend translates codes via i18n, so errors are translatable without server-side locale negotiation.
- Rate limiting + brute force: Flask-Limiter on public endpoints (RATE_LIMIT_VALIDATE default `20 per minute`, RATE_LIMIT_SUBMIT default `5 per minute`), `ProxyFix` configured for the nginx hop so limits key on real client IP; internal endpoints limited generously keyed by API key. **DB-backed lockouts shared across workers**: `ip_lockouts` table — exponential backoff per IP on failed code validation (locked 2^(n−3)×30s once ≥3 consecutive failures, capped 1h, reset on success); code rows invalidated at MAX_FAILED_ATTEMPTS failed submissions. In-memory limiter storage (no Redis — documented as per-worker approximation; the DB lockout is the hard boundary).

**Endpoints** (all JSON, `/api/v1/`):
- `POST /api/v1/validate-code` `{code}` → `{valid, expires_at}` or coded error.
- `POST /api/v1/register` multipart (form fields + optional photo file) → 201 `{username}` or coded error; flow: IP-lockout check → validate+claim code → input validation → LDAP create + group adds (on failure: revert claim, return error) → success.
- `GET /healthz` — compose/CI healthcheck, no auth.
- Internal (header `X-Internal-API-Key`, constant-time compare, 401 generic otherwise): `POST /internal/codes` `{groups[]}` → `{code, url, expires_at}` with `url = {BASE_URL}/register?code=<token>`; `GET /internal/codes?active=true`; `POST /internal/revoke` `{code}`; `GET /internal/groups`.

**DB path** default `/data/codes.db` (volume-mounted).

## Bot

python-telegram-bot v21 (async, long-polling — no webhook infra). Modules: `auth.py` (decorator: sender id ∈ TELEGRAM_ADMIN_IDS else generic "not authorized"; per-user command rate limit ~10/min via deque), `backend_client.py` (httpx → internal API, sends INTERNAL_API_KEY), `picker.py` (pure, testable state machine for the group multi-select), `handlers.py`.

Commands:
- `/gen g1,g2` **and** bare `/gen` → group picker: groups fetched from `GET /internal/groups`, paginated inline keyboard (8/page + ◀▶), ✅/⬜ toggles, Confirm button → create code → reply with the monospace, copyable full link `{BASE_URL}/register?code=<token>`. Text args validated against the real group list before confirming.
- `/list` → active unused codes (hint, groups, expiry, creator).
- `/revoke <code>` → immediate invalidation.
- `/start`, `/help` → usage text.

Tests: pytest with mocked backend client + mocked python-telegram-bot `Update`/`Application` objects — command parsing, authorization, picker state transitions, revoke/list formatting.

## Frontend

Vite + React 18 + TypeScript. Dependencies kept minimal: react, react-dom, react-i18next, i18next, i18next-browser-languagedetector, lucide-react (icons). Tests: Vitest + @testing-library/react + jsdom. Lint: ESLint (typescript-eslint) + Prettier.

- **Design**: strict black/white (#000/#fff), system-ui font stack (zero font deps), large lucide icons per field/action, ≥56px touch targets, generous spacing, CSS custom properties + single stylesheet (no CSS framework), fluid layout validated 320px–4K, transitions respect `prefers-reduced-motion`.
- **Flow** (one action per screen, step wizard with progress dots):
  1. Code screen — reads `?code=`, auto-validates against backend (loading spinner), or shows invalid/expired screen.
  2. Identity — username, first/last name, display name, email; live green-check/red-cross icons as you type.
  3. Password — strength meter, confirm field, show/hide toggle (client mirrors server rules; server still re-validates everything).
  4. Photo — optional, drag-drop/upload, client preview only (server does the real sniff/re-encode), skip button.
  5. Success (big check + username) / failure (red cross + translated reason + retry).
- **i18n**: en + fr JSON files, browser auto-detect + manual switcher, persisted in localStorage; server error codes mapped to translation keys.
- Calls `VITE_API_BASE_URL` (default same-origin `/api/v1` via nginx proxy in compose — no CORS needed in the default deployment; CORS_ALLOWED_ORIGINS still enforced backend-side for split deployments).

## Docker & Compose

- `backend/Dockerfile` — multi-stage: builder (pip wheels) → `python:3.12-slim`, dedicated non-root `appuser`, gunicorn (2 workers × 4 threads), volume `/data`, healthcheck `python -c urllib http://127.0.0.1:8000/healthz`.
- `bot/Dockerfile` — reuses backend base style, non-root, no exposed ports.
- `frontend/Dockerfile` — `node:22-alpine` build (`npm ci`, `vite build`) → `nginx:1.27-alpine` with `nginx.conf`: SPA fallback, gzip, security headers, `client_max_body_size` matching upload cap, `proxy_pass /api/v1 → backend:8000` with `X-Forwarded-For`; healthcheck via busybox `wget`.
- `docker-compose.yml` — frontend, backend (sqlite volume), bot (`depends_on: backend: healthy`); LLDAP external via `LDAP_URL` only. TLS termination by an external reverse proxy (Caddy example in README — Flask/gunicorn never does TLS itself; documented).
